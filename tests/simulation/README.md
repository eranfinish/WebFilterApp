# תרחישי סימולציה — פורמט וסמנטיקה

התכנון הכללי: [docs/SIMULATION-PLAN.md](../../docs/SIMULATION-PLAN.md). כאן מוגדר **מה בדיוק** כל תרחיש אומר. מימוש (Windows, ובעתיד Android) חייב לעבור את התרחישים לפי הכללים האלה.

```bash
cd tests/simulation/tools && npm install && npm run validate
```

## 1. מבנה קובץ

```jsonc
{
  "suite": "time",                      // שם החבילה
  "description": "...",
  "layers": ["engine", "integration", "browser"],
  "platforms": ["windows", "android"],
  "fixture": "family-base",             // ברירת מחדל
  "scenarios": [
    {
      "id": "TIME-001",
      "title": "...",
      "start": "2026-11-01T14:00",      // שעון קיר, באזור הזמן של ה-fixture
      "setup": { ... },                 // תיקון מעל ה-fixture (סעיף 3)
      "steps": [ ... ]                  // מבוצעים לפי הסדר
    }
  ]
}
```

## 3. `setup` — תיקון מעל ה-fixture

| שדה | כלל מיזוג |
|-----|-----------|
| `members` | מיזוג שדות לפי `id` |
| `schedules` | אם מופיע בן משפחה — **מחליף את כל** חלונות הזמן שלו מה-fixture |
| `dailyLimits` | מחליף את המכסה של אותו בן משפחה באותם ימים |
| `rules`, `memberCategories`, `youtubeChannels`, `appRules` | מתווסף |

## 4. שעון

- **זמן מקומי** בכל מקום: `HH:MM` = אותו יום מדומה; `YYYY-MM-DDTHH:MM` = תאריך מלא.
- `at` בצעד = השעון מתקדם לשעה הזו לפני הצעד. אסור לחזור אחורה.
- `browse` מקדם את השעון לסוף ה-session המאוחר ביותר.
- ה-fixture קובע אזור זמן (`Asia/Jerusalem`). **אזור הזמן של המערכת לא משפיע** (`setSystemTimezone` לא משנה תוצאות).

## 5. סמנטיקה של סינון

סדר ההחלטה — כמו ב-[MVP-PLAN.md](../../docs/MVP-PLAN.md) סעיף 6. פרטים מחייבים:

| נושא | כלל |
|------|-----|
| `domain` | מתאים לדומיין עצמו **ולכל תתי-הדומיינים**. `example.com` לא מתאים ל-`example.com.other.net` ולא ל-`notexample.com` |
| `wildcard` `*.example.com` | **רק תתי-דומיינים**, לא את `example.com` עצמו |
| `prefix` `host/path` | המארח לפי כללי `domain`; הנתיב **לא** רגיש לאותיות (עדיף לחסום יותר מאשר לפספס), ומתאים **בגבול מקטע**: `/r/learn` מתאים ל-`/r/learn`, `/r/learn/x`, `/r/learn?q` — לא ל-`/r/learnmore`. תבנית שמסתיימת ב-`/` היא קידומת רגילה |
| `alwaysAllowed` | כלל כזה מחזיר תמיד `allowed_always` — גם בתוך החלון ולפני שהמכסה נגמרה |
| `regex` | RE2, על ה-URL המנורמל המלא |
| ספציפיות | `prefix` > מארח מדויק (`domain` שמתאים בדיוק) > `domain` שמתאים כתת-דומיין / `wildcard` (יותר רמות = יותר ספציפי) > `regex`. תיקו → חסימה |
| קטגוריה | דומיין בקטגוריה מתנהג כמו כלל `domain`. סיבה: `allowed_category` / `blocked_category` |
| כלל אישי מול גלובלי | **כל** כלל אישי שמתאים גובר על כל כלל גלובלי או קטגוריה, גם אם פחות ספציפי |
| תפוגה | `expiresAt` — הכלל פעיל עד הרגע הזה, לא כולל |
| כתובת IP | למשתמש מוגבל: חסום (`blocked_ip_literal`) אלא אם יש כלל `allow` מפורש לאותה כתובת. צורות עשרוניות/הקסה מנורמלות ל-IPv4 רגיל |
| `sub` frame | אותם כללים כמו `main` |
| סכמה לא http/https | `not_applicable` |
| YouTube | הדומיינים של YouTube נקבעים לפי `youtubeMode` **בלבד**, בלי קשר ל-`filterMode` |
| ערוץ YouTube | התאמה לפי `channelId`, או לפי `handle` אם הוא שמור ברשומת הערוץ (לא רגיש לאותיות). במצב "רק מאושרים": בלי זהות ערוץ → `blocked_youtube_unknown`; דף הבית והחיפוש → `redirect_youtube_home` |
| חשבון לא מקושר | חשבון Windows לא-מנהל שעדיין לא קושר לבן משפחה מקבל "רק מאושרים" בלי שום היתר מלבד "מותר תמיד", עד שההורה מקשר אותו |

## 6. סמנטיקה של זמן

| נושא | כלל |
|------|-----|
| חלון | `[start, end)` — ההתחלה כלולה, הסוף לא |
| ימים בלי חלון | אם לבן משפחה יש חלונות כלשהם, יום בלי חלון = אין גלישה. בן משפחה בלי חלונות בכלל = אין הגבלת שעות |
| heartbeat | `browse` = heartbeat כל 30 שניות מ-`from` ועד לפני `to` |
| ספירת דקה | דקה נזקפת **בסופה**, אם היה בה heartbeat פעיל אחד לפחות. גלישה 15:00–17:00 = 120 דקות, נזקפות עד 17:00 |
| מתי לא נספר | `active: false`, מחוץ לחלון, אחרי שהמכסה נגמרה, בהשהייה, במצב שיעורי בית, משתמש ללא הגבלה |
| כפילות | כמה דפדפנים או כמה מחשבים באותה דקה = דקה אחת (איחוד לפי דקה) |
| אזהרות | אירוע `time_warning` כשהנותר מגיע ל-10, 5, 1 |
| מצבים | `ok` · `warn` (נותרו ≤ 10) · `expired` · `outside_window` · `unlimited` |
| `remainingMinutes` | `max(0, limit − used)` |
| `windowEndsAt` | סוף החלון הנוכחי (כולל חלון זמני), או `null` |
| `extendTime` | מוסיף N דקות למכסה של היום. אם עכשיו מחוץ לחלון, או שהחלון נגמר בעוד פחות מ-N דקות — נוסף חלון זמני `[עכשיו, עכשיו+N)` להיום |
| חצות | איפוס בחצות לפי אזור הזמן של ה-fixture, כולל בימי מעבר שעון |
| `pause` | עד `until`: הכול מותר (`allowed_paused`), לא נספר זמן |
| `startHomework` | ל-N דקות: קטגוריית "חינוכי" ו"מותר תמיד" מותרים גם מחוץ לחלון ואחרי המכסה (`allowed_homework` / `allowed_always`); כל השאר `blocked_homework`; לא נספר זמן |

## 7. אפליקציות (שכבת WFP)

| נושא | כלל |
|------|-----|
| דפדפן נתמך | נתיב מתוך `supportedBrowsers` → `allowed_browser` תמיד (הסינון שלו בתוסף) |
| התאמת נתיב | לא רגישה לאותיות; נתיב מלא בלבד. אותו קובץ בנתיב אחר = אפליקציה אחרת |
| אפליקציה מאושרת | `allowed_rule`; אחרי המכסה או מחוץ לחלון → `blocked_daily_limit` / `blocked_time_window` |
| "מותר תמיד" | `allowed_always` גם כשהזמן נגמר |
| כל השאר | `blocked_app_network` |
| מבוגר | `allowed_unrestricted` |

## 8. ריבוי מחשבים ו-Hub

| נושא | כלל |
|------|-----|
| מקור ההגדרות | ה-Hub. פעולות `admin` (ברירת מחדל `scope: hub`) מגיעות מיד לכל סוכן מחובר |
| סוכן מנותק | ממשיך לאכוף לפי החבילה האחרונה שקיבל |
| מכסה משותפת | הסוכן מחשב: הסכום האחרון מה-Hub + הדקות המקומיות שעדיין לא נשלחו |
| חזרה לרשת | ה-outbox נשלח, ה-Hub מחשב איחוד, והתוצאה מגיעה מיד לכל הסוכנים. אם הסכום עבר את המכסה — `expired` מיד (`usedMinutes` יכול להיות גדול מ-`limitMinutes`) |
| `scope: local` | פעולת חירום על סוכן (למשל `pause`). נאכפת מיד בסוכן, ונרשמת כ-`admin_change` ב-Hub כשהסוכן מתחבר |
| `expectTime` בלי `device` | ה-Hub וכל הסוכנים המחוברים חייבים להסכים |

ברמת `engine` הסנכרון מיידי. זמני התפשטות אמיתיים נבדקים ברמה 4.

## 9. שירות לא זמין (`service: down`)

מה שה-NativeHost מחליט לבד:

| חשבון | תוצאה |
|-------|-------|
| מנהל Windows | `allowed_unrestricted` |
| יש `ProfileCache`, משתמש ללא הגבלה | `allowed_unrestricted` |
| יש `ProfileCache`, משתמש מוגבל | "מותר תמיד" → `allowed_always`; כל השאר → `blocked_service_unavailable` |
| אין `ProfileCache` | `blocked_service_unavailable` |

## 10. כתיבת תרחיש חדש

1. מזהה ייחודי בתבנית `<SUITE>-<NNN>`.
2. `title` אומר מה מוכח, לא איך.
3. מעדיפים `checkUrls` לטבלאות של כתובות, ו-`navigate` כשהזמן או המצב משתנים בין בדיקות.
4. כל `expect` עם `reason` — כך כשל מסביר את עצמו.
5. מריצים `npm run validate` לפני commit.
