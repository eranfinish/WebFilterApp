## 1. מה זה

מערכת סינון אתרים משפחתית ל-Windows 10/11 ביתי (לא בדומיין): מחשב הורים אחד (**Hub**) מנהל דרך הרשת הביתית את כל מחשבי הילדים. בכל מחשב רץ **סוכן** שאוכף מקומית, גם כשה-Hub כבוי: תוסף דפדפן כפוי (Edge ו-Chrome) + WFP לפי אפליקציה + מכסת זמן משותפת. הילדים הם חשבונות Windows רגילים, ההורים מנהלים. ממשק הניהול הוא WPF בעברית (RTL). הגרסה הראשונה (DNS מקומי) נכשלה מסיבות ארכיטקטוניות ונשמרת בתגית `legacy-v1` בלבד: [docs/legacy](legacy/), לא משתמשים בקוד שלה.

הגדרת היעד המלאה: [MVP-PLAN §2](MVP-PLAN.md#2-הגדרת-המטרה-מחדש). קריטריוני הצלחה מדידים: §2.4 שם.

## 3. ארכיטקטורה

הפירוט המלא: [MVP-PLAN §3–§4](MVP-PLAN.md#3-ארכיטקטורה). כאן רק התמונה והכללים.

### 3.1 כמה מחשבים

```
        מחשב ההורים                                  מחשבי הילדים
 ┌──────────────────────────────┐              ┌──────────────────────────────┐
 │ WebFilter.Admin (WPF)        │              │ Agent (אותה תוכנה, תפקיד סוכן)│
 │        │ admin pipe          │   HTTPS      │ • אכיפה מקומית (תוסף + WFP)  │
 │ WebFilter.Service  [Hub]     │◄────────────►│ • עותק אחרון של ההגדרות      │
 │ • הגדרות ראשיות (master)     │  TLS הדדי    │ • ספירת שימוש + תור אירועים  │
 │ • בני משפחה, מכשירים, צימוד  │  ברשת הביתית │ • ממשיך לעבוד בלי Hub        │
 │ • צבירת שימוש משותף, דוחות   │◄────────────►│                              │
 └──────────────────────────────┘              └──────────────────────────────┘
```

### 3.2 בתוך מחשב אחד

```
 session של הילד:  Edge / Chrome ─ תוסף WebFilter (MV3, כפוי; כללי DNR, YouTube, מסך חסימה, זמן)
                                   │ Native Messaging
                                   ▼
                          WebFilter.NativeHost.exe  (בהרשאות הילד)
                                   │ Named Pipe  \\.\pipe\WebFilter.Agent   (הזהות מה-token של התהליך)
                                   ▼
 WebFilter.Service (Windows Service, LocalSystem):
   מנוע החלטות · ספירת זמן · מדיניות דפדפן (HKLM + HKCU של ילדים) · WfpManager → WebFilter.Wfp.Native.dll (C++) → WFP
   שומר תהליכים · שומר התוסף · HubSync (סוכן) / HubServer (Hub) · SQLite ב-%ProgramData%\WebFilter (רק SYSTEM ומנהלים)
```

### 3.3 כללי ארכיטקטורה (לא משתנים בלי החלטת המשתמש)

1. רק `WebFilter.Service` פותח SQLite. ממשק הניהול והתוסף מדברים דרך named pipes.
2. זהות הקורא נלקחת מה-token של ה-pipe (ומנתיב ה-exe), לא מתוכן ההודעה.
3. החלטות סינון מתקבלות **במכשיר**. ה-Hub הוא מישור ניהול בלבד; סוכנים ממשיכים לאכוף כשהוא כבוי.
4. נכשלים סגור לחשבונות לא-מנהלים כשהשירות לא זמין.
5. כל קריאות ה-WFP ב-`src/WebFilter.Wfp.Native` (C++, כותרות רשמיות). בלי מבני WFP ידניים ב-C#.
6. DTO של Hub ↔ סוכן נייטרליים לפלטפורמה (`accountId` אטום), כדי שסוכן Android יוכל להצטרף.
7. `SimulationHooks` קיימים רק תחת `#if SIMULATION`.
8. קודי הסיבה הם רשימה סגורה שמשותפת לקוד, לסכמה, לתוכנית ולתרחישים: הוספת קוד משנה את כולם.

### 3.5 פרוטוקולים בקצרה

- **תוסף ↔ שירות:** הודעות JSON ב-Native Messaging, אחר כך ב-pipe (`hello`, `rules`, `decideUrl`, `reportBlockResult`, `requestAccess`, `reportSearch`, `reportOverride`, push של `rulesChanged`). [§10.1](MVP-PLAN.md#101-agent-תוסף--host--שירות).
- **ממשק ↔ שירות:** admin pipe (`getSettings`, `replaceSettings` עם `ifVersion`, `setMember`, `scanAccounts`, `getDiagnostics`, `getAutoBackup`/`setAutoBackup` ועוד). [§10.2](MVP-PLAN.md#102-admin-ממשק--שירות).
- **Hub ↔ סוכן:** HTTPS עם TLS הדדי. צימוד בקוד של 12 תווים (10 דקות): ההוכחה היא `HMAC-SHA256(code, CSR ‖ SHA-256(עלה התעודה של שרת ה-TLS))`. שימו לב: ההערה ב-`HubApi.cs` אומרת "תעודת ה-CA", וזה שגוי, והקוד הנכון. SSE לדחיפת שינויים. [§10.3](MVP-PLAN.md#103-hub--agent-https-tls-הדדי).
- **התראות להורים:** `\\.\pipe\WebFilter.Notify`, קריאה בלבד, רק לחשבון מנהל.
- **סדר החלטה (סינון):** [MVP-PLAN §6](MVP-PLAN.md#6-סמנטיקה-של-החלטת-סינון) והתרחישים ב-`tests/simulation/scenarios/engine`.

## 4. כללי עבודה (תמצית CLAUDE.md)

- **תרחיש קודם:** שינוי בסינון, זמן, YouTube, אפליקציות או סנכרון מעדכן `tests/simulation/scenarios/**` ו-`tests/simulation/README.md` באותו שינוי, ו-`npm run validate` עובר. אם קוד ותרחיש לא מסכימים, התרחיש קובע עד שהמשתמש מחליט אחרת.
- **גבולות:** נשארים ב-[MVP-PLAN §2.2](MVP-PLAN.md#22-בתוך-ה-mvp). מה ש-§2.3 מוציא החוצה דורש אישור מפורש. (Android אושר כפרויקט המשך; ראו [סעיף 6](#6-סוכן-android-מאושר-לא-התחיל).)
- **אבן דרך מסתיימת רק בבדיקה במצב אמיתי** (שירות מותקן, חשבון ילד אמיתי, VM). הרצת קונסול לא נחשבת.
- **במחשב הפיתוח לא מריצים** את ה-MSI, `WebFilter.Service.exe cleanup`, ולא כותבים מדיניות מכונה או מסנני WFP. בדיקות עם הרשאות מורמות רצות במעבדה. בדיקות יחידה משתמשות ברישום ובמנוע WFP מדומים.
- **קוד:** .NET 10, `nullable`, אזהרות כשגיאות, namespaces בקבצים. WPF בלי לוגיקה ב-code-behind.
- **שפה:** קוד, מזהים, הערות והודעות קומיט באנגלית. מסמכים למשתמש בעברית. שיחה עם המשתמש בעברית.
- **Git:** מפתחים על `v2` או ענפי פיצ'ר ממנו. לא נוגעים ב-`main` ו-`legacy-v1`. **לא דוחפים בלי לשאול.** הודעת קומיט מסתיימת בשורת ה-`Co-Authored-By` שהסשן מקבל.
- **הריפו בבעלות חשבון Windows אחר:** רשום ב-`safe.directory` הגלובלי של git.
- **דיווח:** אם בדיקה נכשלה או שלב דולג, אומרים את זה במפורש, עם הפלט. לא מציגים כמאומת מה שלא נבדק.

## 7. עבודה פתוחה

### 7.1 חיפוש ערוצים ב-YouTube לא מופיע אצל הילד (נבדק 2026-11-15, **לא נפתר**)

**הדיווח:** המשתמש סימן "אפשר לחפש ערוצים" ובחר ל-YouTube של הילד "רק ערוצים מאושרים", ובכל זאת הילד לא רואה את תיבת "חפש ערוץ". אחר כך: "עובד בכרום בלבד כנראה".

**איפה התיבה מופיעה:** רק בדף "הערוצים שלי ב-YouTube" של התוסף (`extension/pages/my-channels.html`, `extension/src/pages/my-channels.ts`), שאליו התוסף מפנה כניסה לדף הבית של YouTube. היא מוצגת כש-`MyChannelsReply.channelSearch` נכון.

**שרשרת התנאים (כולם נבדקו בקוד, כולם נראים תקינים):**
`setMember` ב-`AdminPipeServer.Patch` → `BundleMapper` (בשני הכיוונים) → `ExtensionPolicy.Of` (רק למוגבלים) → `AgentSession.Rules` (`AgentFeatures`) → `protocol.ts: normalizeFeatures` → `controller.channelSearch` (דורש `features.youTubeChannelSearch` **וגם** `rules.youTube.mode === "allowlist"`, ורק כש-`ready` ולא `unrestricted`) → `my-channels.ts`.

**מצבים שבהם התיבה לא תופיע גם כשהכול מוגדר נכון:**
- מחוץ לחלון השעות או שהמכסה נגמרה: YouTube חסום (דף חסימה, לא "הערוצים שלי"). (נבדק: הוספת זמן לילד לא שינתה את התוצאה.)
- מצב שיעורי בית (`YouTubeMode.Off`) או השהיה (`unrestricted`).
- חשבון Windows לא משויך לבן משפחה, או חשבון מנהל: מצב `baseline` או `off`, בלי ההגדרות.
- התוסף 0.3.0 ומטה: חיפוש הערוצים נוסף ב-0.3.1.

**מה ידוע:** גרסת התוסף שהמשתמש דיווח היא 0.3.1 (לא ידוע באיזה דפדפן). הסוכן אצל הילד הוא 0.7.22. התכונה, לפי המשתמש, עובדת ב-Chrome ולא ב-Edge.

**הצעד הבא:** לבדוק ב-`edge://extensions` של הילד את גרסת התוסף ב-Edge (חשד: עדיין 0.3.0, ואז לעדכן). אם גם שם 0.3.1: להריץ `npm run verify:edge` ו-`npm run e2e:real` ב-`extension/` ולחפש הבדל בין Edge ל-Chrome (ה-Edge הוא תוסף שנבנה מאותו קוד; בחנות Edge הוגש ב-2026-10-26). לבקש מהמשתמש צילום של חלון התוסף (משתמש, מצב, שגיאה) ושל מה שהילד רואה ב-`youtube.com`.

**פער בדיקות שנמצא:** `HubSyncTests` לא בודק שהמתג `youTubeChannelSearch` מגיע מה-Hub לסוכן דרך הסנכרון (הוא נבדק בנפרד ב-`BundleMapper` ובצד הסוכן). כדאי להוסיף בדיקה כזאת.

**אין להניח** שהתיקון נמצא בקוד לפני שמצמצמים: ייתכן שהסיבה היא בהתקנה, בגרסה או בהגדרה, לא בקוד.
