# מערך סימולציות — בדיקת הסינון אחרי כל בנייה

## 1. המטרה

הגרסה הקודמת "עברה" בדיקה אחת בקונסול ולא עבדה במציאות. כאן כל התנהגות של הסינון מוגדרת **מראש** כתרחיש — משפחה מדומה, ציר זמן, פעולות, ותוצאה צפויה — ואותו תרחיש רץ אוטומטית על כל רמה של המערכת אחרי כל בנייה.

עקרונות:
1. **התרחישים הם המפרט.** אם יש ויכוח מה המערכת צריכה לעשות — התרחיש מכריע. משנים התנהגות רק יחד עם התרחיש.
2. **קובץ אחד, כמה מריצים.** אותו קובץ JSON רץ ברמת המנוע (מילישניות), מול שירות אמיתי, ובדפדפן אמיתי. בעתיד גם מול מימוש Android.
3. **שעון מדומה.** יום שלם של גלישה מסומלץ בשניות — מלבד רמה 4, שבה רץ קוד השחרור האמיתי.
4. **דטרמיניסטי.** בלי אינטרנט ובלי תלות בשעה האמיתית (מלבד חבילת live אחת מול YouTube).

## 2. חמש הרמות

| רמה | שם | מה רץ | זמן | מתי רצה | אבן דרך |
|:---:|-----|-------|-----|---------|:---:|
| 1 | `engine` | `WebFilter.Core` בתוך התהליך: Hub + סוכנים מדומים, שעון מוזרק, רשת מדומה | שניות | כל build | M1 |
| 2 | `integration` | שירות אמיתי (build `Simulation`) + pipes + SQLite אמיתי + Hub אמיתי, לקוחות בדיקה | דקות | כל build | M2, M6 |
| 3 | `browser` | Chromium/Edge אמיתי + התוסף (unpacked) + NativeHost + שירות; שרת אתרים מקומי | דקות | כל build | M3 |
| 4 | `system` | מעבדת Hyper-V: MSI אמיתי, חשבונות ילד אמיתיים, מדיניות ו-WFP אמיתיים | עשרות דקות | לילי / לפני שחרור | M4, M6–M8 |
| 5 | `load` | תעבורה סינתטית, soak של 24 שעות | שעות | לפני שחרור | M8 |

כל תרחיש מצהיר באילו רמות הוא רץ (`layers`) ועל אילו פלטפורמות (`platforms`).

### 2.1 רמה 1 — מנוע

- מריץ xUnit שטוען את כל קבצי `tests/simulation/scenarios/**.json` שמסומנים `engine`, ויוצר מהם בדיקה לכל תרחיש
- בונה בזיכרון: Hub (מהדר חבילות, צבירת שימוש) + סוכן לכל מכשיר + `FakeClock` + `FakeNetwork` (לניתוק Hub)
- `browse` מתורגם ל-heartbeats כל 30 שניות; `navigate` / `youtube` / `app` קוראים ישירות ל-`DecisionService`
- כשל מדווח עם מספר הצעד, הקלט, הצפוי והתקבל
- **Android:** מריץ מקביל ב-Kotlin יטען את אותם קבצים (תרחישים עם `"android"` ב-`platforms`)

### 2.2 רמה 2 — אינטגרציה

- השירות רץ כתהליך נפרד בתצורת `Simulation`: `SimulationHooks` חושף pipe בדיקה לשליטה בשעון ולאיפוס מצב. **הקוד הזה לא קיים ב-Release** (`#if SIMULATION`, ובדיקת CI שמוודאת זאת)
- לקוח בדיקה מתחבר ל-Agent pipe כמו NativeHost, ול-Admin pipe כמו ממשק הניהול
- בודק גם מה שאין ברמה 1: זיהוי SID מה-token, דחיית admin pipe בלי הגבהה, migrations, outbox ו-idempotency, צימוד ו-TLS הדדי בין Hub לסוכן (שני תהליכים על אותה מכונה)
- תרחישי `multi-device` רצים עם Hub אחד ושני סוכנים כתהליכים נפרדים; ניתוק = חסימת הפורט

### 2.3 רמה 3 — דפדפן

- Playwright מפעיל את **Edge המותקן** (`channel: "msedge"`) עם התוסף כ-unpacked (`--load-extension`) ו-NativeHost רשום ב-HKCU של משתמש הבדיקה (רק בסביבת הבדיקה). הוכח ב-S3; ה-Chromium של Playwright לא עולה על Windows 10.0.26220
- **שרת אתרים מקומי** עונה לכל שם מארח: `--host-resolver-rules="MAP * 127.0.0.1"` + `ignoreHTTPSErrors`. כל דף מחזיר כותרת עם שם המארח והנתיב, כך שהמריץ יודע מה נטען
- **דפי YouTube מדומים** (fixtures) שמחקים את המקורות שאומתו ב-S4: `#movie_player.getPlayerResponse()`, `#shorts-player`, `ytd-browse.data`, `PLAYER_VARS.embedded_player_response`, ניווט SPA עם `yt-navigate-finish` — **וגם** מקורות ישנים (`meta`, `og:url`, `ytInitialData` של הדף הקודם), כדי לוודא שהמנוע לא נופל בהם
- התוצאה נקבעת לפי כותרת הדף: דף אתר מדומה = מותר; `WebFilter · חסום` = חסום (הסיבה נקראת מהדף)
- בודק גם: fail-closed כשהשירות כבוי, אזהרות זמן, מעבר ל"הזמן נגמר" בלשוניות פתוחות, דף "הערוצים שלי", דיווח חסימה ובקשת גישה
- **חבילת live** (שבועית, לא חוסמת build): כמה תרחישי YouTube מול האתר האמיתי, כדי לזהות שינוי במבנה הדף

### 2.4 רמה 4 — מערכת (מעבדת VM)

- **מעבדה:** Hyper-V עם 3 מכונות Windows 11 (Home ו-Pro): `lab-hub`, `lab-kids`, `lab-laptop`, לא בדומיין, עם snapshot נקי
- **מתזמר:** `Invoke-LabSimulation.ps1` — משחזר snapshot, מתקין MSI (Hub / סוכן + צימוד), יוצר חשבונות לפי ה-fixture, ומריץ צעדים בתוך המכונות דרך PowerShell Direct
- **הפעלה כילד:** התחברות אוטומטית לחשבון הילד ב-VM; הדפדפן נפתח בסשן שלו ומופעל דרך UI Automation (FlaUI) — הקלדה בשורת הכתובת וקריאת כותרת החלון. כך לא צריך DevTools, שחסומים לילד במדיניות
- **אתרים:** שרת אתרים מדומה על `lab-hub` עם דומיינים מסוג `.test` ו-CA של המעבדה שמותקן במכונות
- **זמן:** בלי שעון מדומה (קוד שחרור). תרחישי זמן ברמה 4 משתמשים במכסות קצרות (2–3 דקות) וממתינים בפועל
- **מה נבדק כאן בלבד:** התקנה כפויה מהחנות, מדיניות HKLM/HKCU, WFP, ProcessGuard, אתחול, Safe Mode, עדכון דפדפן, הסרה נקייה, וזמני התפשטות (< 5 שניות) ברשת אמיתית

**תרחישי הגנה (חייבים להיכשל בחשבון ילד):**
גלישה בסתר · מצב אורח · פרופיל חדש · כיבוי/הסרת התוסף · מצב מפתח · DevTools · הריגת ה-NativeHost · host מזויף ב-HKCU · דפדפן נייד שלא הותקן · דפדפן מ-Microsoft Store · דפדפן נתמך שהועתק לנתיב אחר · שינוי אזור זמן · הגדרות פרוקסי/VPN של Windows · אפליקציית VPN · אפליקציה לא מאושרת עם רשת · Safe Mode · אתחול · עצירת השירות או מחיקת קבצים בלי הרשאות מנהל

**תרחישים חיוביים:** מבוגר גולש ומפעיל אפליקציות כרגיל · אתר מאושר עם משאבים חיצוניים נטען מלא · אפליקציה מאושרת מתחברת · שינוי מה-Hub נאכף בשני המחשבים תוך 5 שניות · Hub כבוי → הסוכנים ממשיכים · הסרת MSI מנקה מדיניות ומסנני WFP

### 2.5 רמה 5 — עומס ו-soak

- **מיקרו:** BenchmarkDotNet — החלטה עם 10,000 כללים (יעד p99 < 2ms), הידור חבילה ו-DNR
- **עומס:** NBomber — 50 לקוחות Agent pipe במקביל, 20 ניווטים בשנייה כל אחד, heartbeats
- **soak:** 24 שעות במעבדה עם גלישה סינתטית; מדידת זיכרון (< 100MB), CPU במנוחה (< 1%), גודל DB, דליפות handles

## 3. דוחות

- כל מריץ מוציא **JUnit XML** (ל-CI) ו-**דוח HTML** אחד מאוחד: תרחיש → צעדים → צפוי מול התקבל, עם קישור לקובץ ולשורה
- תיקיית פלט: `tests/simulation/reports/` (לא נשמרת ב-git)
- ברמה 4: צילומי מסך של כל צעד שנכשל + לוגים של השירות מהמכונה

## 4. מבנה התיקייה

```
tests/simulation/
  README.md                 פורמט, סמנטיקה, איך כותבים תרחיש
  schema/scenario.schema.json
  fixtures/family-base.json משפחה מדומה: 4 בני משפחה, 3 מחשבים
  scenarios/
    engine/                 רמות 1–3 (מנוע, ומשם גם אינטגרציה ודפדפן)
    system/                 רמה 4 (יתווסף ב-M4)
  tools/validate.mjs        בדיקת סכמה + עקביות (מזהים, זמנים, הפניות)
  runners/                  (יתווספו לפי אבני הדרך)
    engine/  integration/  browser/  lab/  load/
  web-fixtures/             דפי אתרים ו-YouTube מדומים (M3)
```

## 5. שילוב באבני הדרך

| אבן דרך | מה נבנה במערך | תנאי סיום |
|:---:|---|---|
| M0 | הסכמה, ה-fixture, קטלוג תרחישי המנוע, כלי בדיקה — **קיים** | `npm run validate` עובר |
| M1 | מריץ רמה 1 | כל תרחישי `engine` עוברים |
| M2 | מריץ רמה 2 + `SimulationHooks` | תרחישי `integration` עוברים |
| M3 | מריץ רמה 3, שרת אתרים, fixtures של YouTube | תרחישי `browser` עוברים |
| M4 | מעבדת VM, מתזמר, תרחישי `system` | כל תרחישי ההגנה נכשלים כמצופה |
| M6 | ריבוי מחשבים ברמות 2 ו-4 | תרחישי `multi-device` עוברים |
| M8 | רמה 5 | יעדי ביצועים ו-soak |

## 6. מה קיים עכשיו

קטלוג תרחישי המנוע (רמות 1–3) ב-`tests/simulation/scenarios/engine/`:

| קובץ | נושא |
|------|------|
| `rules.json` | התאמת דומיין/wildcard/קידומת/regex, ספציפיות, כללים אישיים מול גלובליים, קטגוריות, תפוגה, מצב "רק מאושרים" |
| `normalization.json` | נרמול כתובות: אותיות, נקודה סופית, פורט, userinfo, percent-encoding, IDN, כתובות IP |
| `time.json` | חלונות זמן, מכסה, אזהרות, הארכה, חצות, שעון קיץ, idle |
| `pause-homework.json` | השהייה, מצב שיעורי בית, "מותר תמיד" |
| `youtube-parse.json` | פענוח כל צורות ה-URL של YouTube |
| `youtube-decisions.json` | החלטות YouTube לפי מצב בן המשפחה |
| `apps.json` | החלטות רשת לאפליקציות (שכבת WFP) |
| `multi-device.json` | מכסה משותפת, מניעת ספירה כפולה, ניתוק Hub, התפשטות הגדרות |
| `fail-closed.json` | התנהגות כשהשירות לא זמין |
| `access-requests.json` | בקשות גישה: אישור לדקות/להיום/לתמיד, לאתר או לדף, דחייה ו-cooldown, איחוד והגבלת הצפה, תור כשה-Hub מנותק |

תרחישי `system` (רמה 4) ייכתבו ב-M4, יחד עם המעבדה.
