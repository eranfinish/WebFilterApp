# WebFilter browser extension

Manifest V3 extension for Edge and Chrome (milestone M3). It is force-installed by browser policy from the Chrome Web Store and Microsoft Edge Add-ons (unlisted, same item and name "WebFilter" as the S1 build in `store/extension-s1/`). It enforces the rules the WebFilter service compiles for the signed-in Windows user, the time limits, YouTube channels, and the protection features (jump guard, YouTube Shorts, search-term log, ad blocking). Design: [MVP-PLAN.md §4.4, §6–§8.1, §10.1](../docs/MVP-PLAN.md), [PROTECTION-SPEC.md §6–§9, §12](../docs/PROTECTION-SPEC.md). Semantics: [tests/simulation/README.md](../tests/simulation/README.md).

## Build and test

Requires Node.js 20.19+ (Vitest 4 / Vite 7). Versions are pinned exactly in `package.json`. `.npmrc` sets `legacy-peer-deps`, because npm 10.8 crashes on vitest's optional peer chain (`Cannot read properties of null (reading 'edgesOut')`).

```bash
cd extension
npm install
npm run build          # → dist/        production build (no test hooks; the build fails if any are found)
npm run build:test     # → dist-test/   test build: adds globalThis.wfTest in the service worker
npm test               # Vitest unit tests (pure modules + the controller against a chrome.* mock and a fake host)
npm run typecheck      # tsc --noEmit
npm run verify:edge    # builds both, then loads them into the installed Edge with Playwright (see below)
npm run e2e:real       # level 3: dist-test in Edge + the real native host + the real service (Simulation builds)
```

### Level 3: the real chain (`npm run e2e:real`)

`harness/e2e-real.mjs` builds the service and the native host (`-c Simulation`) and `dist-test/`, starts `WebFilter.Service.exe` as a hub with a temp data folder, unique pipe names and the family fixture (noa's account = the current Windows user), registers the host for Edge, and loads `dist-test` with a simulated policy install. It then checks, as noa: the handshake and the service's DNR rules; a blocked site with the service's reason and the recorded event; an allowed site; a live `addRule`; a request sent from the block page and approved through the admin pipe; time up and back (`setClock`); pause and resume; ad blocking switched on and off (`setMember`); and the service killed and restarted. Results: `harness/results/e2e-real.json` (plus the service and worker logs).

- The only change outside the temp folder is `HKCU\Software\Microsoft\Edge\NativeMessagingHosts\com.webfilter.host`, pointing at the temp manifest. The run stops if that key already exists, and removes it at the end, on errors and on Ctrl+C. `npm run e2e:real -- --cleanup` removes a leftover of an interrupted run (only if it points at a manifest of this harness). `--no-build` skips the builds; `HEADED=1` shows the browser.
- The hub listens on 127.0.0.1 with a random port (no firewall prompt) and the service never writes browser policies.
- The developer account is usually an administrator, whose service-down fallback is "unrestricted". The harness sets `WEBFILTER_SIMULATE_STANDARD_USER=1` (read by Simulation hosts only) so the fallback behaves as for a child's standard account.

`dist/`, `dist-test/`, `node_modules/`, `package-lock.json` and `harness/results/` are not committed.

### Load unpacked

`edge://extensions` (or `chrome://extensions`) → Developer mode → **Load unpacked** → choose `extension/dist`. An unpacked extension reports `installType: "development"`, so it stays **inert**: fail-closed off, no native host, popup says "not installed by policy". That is what store reviewers see too. To exercise the enforcing path without a policy, load `dist-test` and, in the service worker console, run `await wfTest.simulatePolicyInstall()`.

## How it works

### Startup and fail-closed

On every service-worker start:

1. `chrome.management.getSelf()`. If `installType !== "admin"`, the extension is **inert**: it disables `failclosed`, clears its rules, never opens the native host, and only answers the popup. If the install type can't be read, the extension is treated as policy-installed (fail closed).
2. If it is policy-installed, it enables `failclosed` (and the `ads` ruleset, below), clears the dynamic and session rules, and connects `chrome.runtime.connectNative("com.webfilter.host")`. The port stays open, which keeps the worker alive (spike S2).
3. `hello {extVersion, browser, extensionId}` → `helloResult`, then `getRules` → `rules`. The dynamic rules are installed first, then the time state is applied, and only then is `failclosed` disabled. Both reply sources count: `source: "service"` and the native host's own fallback (`source: "host"`). For an unrestricted user, all rules are removed and `failclosed` is turned off. For a parent with the family's baseline protection (mode `baseline`, below) the rules are installed like a member's.
4. When the port closes (host missing or exited, handshake error or timeout, rules that cannot be installed): `failclosed` and `ads` on, dynamic and session rules cleared, then a reconnect with backoff of 1, 2, 4, 8, 16 and 30 s. The 30 s heartbeat alarm restarts the reconnect if the worker lost its timer. A host that answers by itself (service down) checks the service pipe every 3 s and exits once the service is back, so the extension reconnects to the service.

Pages that hit the static fail-closed rule cannot carry the original URL, so the worker remembers what each frame tried to load (`webNavigation.onBeforeNavigate`). Once connected, the fail-closed page goes back there by itself (the browser-startup case).

### Messages (MVP-PLAN §10.1, `src/WebFilter.Contracts/Agent/AgentMessages.cs`)

Every message the extension sends starts with `type`, then `v: 1` and `id`. System.Text.Json polymorphism needs the discriminator first. Replies echo the id.

| Extension → host | Reply | Used for |
|---|---|---|
| `hello {extVersion, browser, extensionId}` | `helloResult {user, mode, source, serviceAvailable, rulesVersion, serverVersion}` | handshake |
| `getRules` | `rules {rulesVersion, dynamicRules, timeUpSessionRules, youTube, time, features?, mode?}` | after hello, and on every `rulesChanged` |
| `heartbeat {focused, idle, hasWebTab}` | `timeState` | every 30 s (`chrome.alarms`), plus 1 s after focus, idle or active-tab changes |
| `reportBlock {url, reason, ruleId?}` | `reportBlockResult {decision, reason, ruleId?, category?, canRequest, requestKind}` | a block page's first load |
| `decideUrl {url}` | `decideUrlResult` (same fields) | a reload of the same block page (records nothing) |
| `requestAccess {kind, target?, minutes?, note?}` | `requestAccessResult {result, requestId?}` | block page / time-up page buttons |
| `reportSearch {engine, query, url}` | `error {code: "ok"}` | once per distinct search while `features.logSearches` (below) |
| `reportOverride {url, reason: "blocked_jump"}` | `error {code: "ok"}` | a teen's "פתח בכל זאת" on a jump block |
| `error {code: "dnr_rules_dropped", message}` | (`error unsupported`, ignored) | rules the browser refused |

`rules` carries `features: {jumpGuard, blockYouTubeShorts, logSearches, canOverrideJump, blockAds}` (PROTECTION-SPEC §6, §12). A missing object or a flag that is not exactly `true` counts as off; the extension also treats them as off for an unrestricted account and while it is not connected. It also carries the account's `mode` (`unrestricted | blocklist | allowlist | baseline`, §13), which wins over the hello's: a re-linked account or a changed baseline switch applies with `rulesChanged`, without a new hello. A missing or unknown `mode` (an older service, the host fallback) leaves the hello's.

| Host → extension push | Action |
|---|---|
| `rulesChanged` | `getRules` again (coalesced) and install only the rules that changed (diff by id + content) |
| `timeState` | apply: session rules, badge, warnings, time-up tabs |
| `accessDecided {requestId, status}` | if approved, refresh the rules first, then tell the pages. The block page for that request navigates back to its URL (the time-up page does so once time is back) |
| `chunk {chunkOf, index, count, data}` | frames over 1 MB: the base64 slices are decoded and joined as bytes, then parsed as the original message |

Error replies reject the request. `error {code: "ok"}` (reportBlock on services before v2, reportSearch, reportOverride) counts as an acknowledgement. When `service_unavailable` comes from the host fallback, the block page shows the "service is not running" text.

### Enforcement

- **Dynamic rules** are passed to `updateDynamicRules` exactly as the service sent them, with null members stripped. If Chrome refuses the whole update (for example a regex too large for RE2), nothing changes and the previous rules stay. Every `regexFilter` rule is then checked with `isRegexSupported`, the rejected ones are dropped, the update is retried once, and the dropped ids are logged, shown in the popup, and sent as `error dnr_rules_dropped`. The same applies to session rules.
- **Time up**: while `time.state` is `expired` or `outside_window`, `timeUpSessionRules` is installed as session rules, and removed when time is back. When time runs out, open http(s) tabs that the session rules would block move to `timeup.html#<url>`. Always-allowed sites stay, decided by `dnr-match.ts` against the session rules. When time comes back, those pages return.
- **In-page navigations** (history API, which DNR never sees): on `webNavigation.onHistoryStateUpdated`, a top frame whose new address the installed rules would block is sent to `blocked.html#<url>`. The worker does nothing when a rule that applies cannot be evaluated in JS (RE2-only syntax), so an allowed page is never blocked by mistake. Sub-frames are not covered.
- **Badge**: remaining minutes when 10 or fewer, `0` when time is up, `!` while fail-closed. **Notifications** at 10, 5 and 1 minutes, each at most once a day (re-armed if a parent adds time), and when a parent answers a request sent from this browser.
- **Blocks inside frames** (an ad slot from a blocked ad network such as the `ads-popups` list, an embed): `blocked.html` in a frame (`window.top !== window`) is a quiet, empty, transparent placeholder with no text or buttons, and it sends neither `reportBlock` nor `decideUrl`, so a news page with blocked ads neither looks broken nor floods the parents' activity log. The worker enforces it too: a `wf:reportBlock` from a frame (the browser's `frameId ≠ 0`, whatever the page says) is answered locally and nothing goes to the service. A fail-closed frame still retries its own address once connected (it only asks the worker). Top-level block pages are unchanged. A blocked YouTube embed is therefore quiet too: the channel request is offered only on a top-level block page.
- **Block page reason**: compiled rules redirect to `blocked.html#<full URL>` with no reason. The page asks the worker, which sends `reportBlock` (first load) or `decideUrl` (reload) and shows the **service's** reason, category, and whether and what to request. The reason the extension sends along is a guess from the matched rule (`explain.ts`); it stands only for `blocked_youtube_channel` and `blocked_youtube_unknown`. That guess is also what the page shows when the service can't answer (disconnected, or an older service). The page offers a request only when the service says `canRequest` and an approval could help. It offers none for homework, YouTube off, an unknown channel, or service down (MVP-PLAN §8.1). `decision: "allow"` (stale rules) shows "allowed now" with a retry button, and the page returns after the rules refresh.
- **YouTube**: `yt-main.js` (MAIN world, every YouTube frame, `document_start`) finds the channel of the current URL from trusted sources only and posts it to `yt-bridge.js`. The bridge hides the page until the decision arrives (allowlist mode), asks the worker, and then reveals the page or navigates to the block page (`?reason=…&channel=UC…#url`) or to `my-channels.html` (home and search). The decision is `Decider.YouTube()` on the last rules: unrestricted member → time → mode → channel, matched by id or stored handle. In allowlist mode the side recommendations and the end screen are hidden. SPA navigations are caught by `yt-navigate-finish`, URL polling and `webNavigation.onHistoryStateUpdated`.

### Protection features (PROTECTION-SPEC §6–§9)

Reason codes `blocked_image_search`, `blocked_jump` and `blocked_youtube_shorts` have a sentence in both locales and **no request button**: they come from member settings, and approving the URL would not lift them (image search and Shorts are switched off by the parent; a jump target can be opened by typing it). Image search itself is blocked by the service's DNR rules; the extension only shows the service's reason. `blocked_jump` and `blocked_youtube_shorts` are decided by the extension: the block page carries them in `?reason=`, `reportBlock` sends them, a reload never asks `decideUrl`, and a service answer of `decision: "allow"` is ignored for them.

**Jump guard** (`features.jumpGuard`, `shared/jump.ts`, `background/jump-guard.ts`). Sites are compared by registrable domain (below).
- A tab or window a page opens (`webNavigation.onCreatedNavigationTarget`: `window.open`, `target=_blank`, also middle-click and "open in new tab" on a link) whose page is on another site than the opener's tab goes to `blocked.html?reason=blocked_jump#<url>`. A tab opened from the browser's or the extension's own pages is not guarded.
- An automatic client redirect (`transitionQualifiers` has `client_redirect`, not `forward_back`) to another site goes there too. In Edge 156 that flag marks meta refresh and script redirects that run while the page is loading. The search engines' click-through pages (Bing `/ck/a`, DuckDuckGo `/l/`, Google `/url`, YouTube `/redirect`) are exempt: the member clicked the result.
- Never blocked: the member's own link click in the same tab (search results), forms, server redirects, typed addresses, bookmarks, Back/Forward, the browser's pages.
- **The race with the new tab's first navigation**: (1) a cross-site target is sent to the block page with `tabs.update` in the same task as the event, which cancels the navigation if it has not committed; (2) a session rule for that tab only (`tabIds`, `excludedRequestDomains: [opener's site]`, priority 327,680 above every compiled rule) redirects any other site's top-level request before it is sent: server redirects of the first navigation, and `opened.location = …` after `window.open('about:blank')`; it is removed when the tab's first page or the block page commits (so a typed address works in that tab), or after 60 s; (3) `onBeforeNavigate` re-checks the tab until it shows something, and `onCommitted` is the backstop. In the Edge harness the target of `window.open` and of the delayed `opened.location` never reached the server. A client redirect is only visible at commit, so its page has started to load when the block page replaces it.
- A tab a page opened stays guarded until it shows a page of the opener's site or the member navigates it (typed address, bookmark): until then a page-driven load to another site is blocked at commit too.
- **"פתח בכל זאת"** (`features.canOverrideJump`, teens): the block page's button sends `wf:overrideJump`. The background accepts it only from a top-level `blocked.html?reason=blocked_jump` page for the same URL, sends `reportOverride {url, reason: "blocked_jump"}` (without waiting; an older service's error is logged), stops guarding that tab, and opens the URL in it. The opener's next jump is blocked again, and so is a client redirect of the page that opened.
- The block page reports with `reportBlock {url, reason: "blocked_jump"}` on its first load.

**Registrable domain** (`shared/registrable-domain.ts`). A small built-in approximation of the Public Suffix List: IP literals and single-label hosts are their own site; a list of second-level suffixes of common country domains (`co.il`, `org.il`, `ac.il`, `gov.il`, `co.uk`, `com.au`, `co.jp`, `com.br`, …) and of hosting platforms (`github.io`, `blogspot.com`, `translate.goog`, …); any other two-letter country domain with a generic second label (`com`, `net`, `org`, `edu`, `gov`, `ac`, `co`, …) is treated as a suffix too; otherwise the last two labels. Limits: deeper or unlisted suffixes count as registrable (`a.city.state.us` → `state.us`), platforms outside the short list count as one site, and the list's wildcard and exception rules are not modelled. A wrong answer only changes whether a cross-site jump is noticed; it never allows a URL the rules block.

**YouTube Shorts** (`features.blockYouTubeShorts`, `shared/shorts.ts`). A `/shorts` page on youtube.com (www, m) is blocked with `blocked_youtube_shorts`: full loads by an extension session rule (priority 196,624: above the YouTube host rule, below the time-up rules; not installed while YouTube is off), in-site navigations by `onHistoryStateUpdated` in the background, and `decideYouTube()` blocks them too when the content script reports one (after time and "YouTube off", before any channel or mode allows it). While it is on, the bridge hides with CSS (one rule per selector): Shorts shelves on home, search, subscriptions and watch pages, single Shorts results, the "Shorts" entry of the side menu, the mini menu and the mobile bottom bar, and a channel's "Shorts" tab. Not covered: a Short opened as `/watch?v=<id>` or `youtu.be/<id>` (an ordinary video of its channel), and YouTube markup renamed after 2026.

**Search-term log** (`features.logSearches`, `shared/search.ts`). Google `/search?q=` (any google.<country>), Bing `/search?q=` (also `/images/search`, `/videos/search`, `/news/search`), YouTube `/results?search_query=`, DuckDuckGo `/?q=` (also `/html/`, `/lite/`), recognised from top-frame commits and in-page address changes, and from a block page's first report (a blocked search, such as an image search, is a search too). `reportSearch {engine, query, url}` is sent once per engine and query (whitespace collapsed, case-insensitive): not for reloads, Back/Forward, prerendered pages, later result pages (`start`, `first`, `s`), or the same search again within 10 minutes of its report. Only while connected to the service; a report lost with the connection is retried at the next sighting. The popup says "החיפושים שלך גלויים להורים" while it is on.

**Ad blocking** (`features.blockAds`, PROTECTION-SPEC §12, `background/dnr.ts`). The static ruleset `ads` (`rulesets/ads.json`, `"enabled": false` in the manifest) is enabled with `updateEnabledRulesets` while the rules say `blockAds` (the service sends it for children and teens with the switch on, and false while the member is paused), and disabled otherwise: unrestricted, inert, the native host's own answers. While fail-closed it is on, the strictest state (new pages and frames are blocked anyway; pages already open stop loading ads). The worker remembers what it last set and changes the ruleset only when that changes; a refused change is logged and tried again with the next rules.

- **What it blocks**: every request type but `main_frame` (`excludedResourceTypes`) to EasyList's ad servers — scripts, images, frames, `fetch`/XHR, beacons, media, fonts, websockets — on every site, the allowed ones included. `$third-party` domains (`domainType: "thirdParty"`) only from other sites' pages, so their own pages keep working. Page loads stay with the URL rules and the `ads-popups` list. Generated from a pinned EasyList commit by `tools/starter-lists/ad-ruleset.mjs` (whole-domain rules only, EasyList's exceptions per host, never Google/YouTube/Microsoft/Apple core hosts, `gov.il` or the `educational` and `school-tools` domains); see `data/starter-lists/README.md`. 51,874 domains in 65 rules.
- **Priorities**: block rules only, priority 1. The compiled rules filter `main_frame` and `sub_frame` only and never use `allowAllRequests` (nor do the extension's own rules), so nothing outranks an ad rule for a script, image or request. For a frame, a URL rule that matches it (priority 2 and up) still decides; the allowlist default (priority 1, a redirect) loses to the ad block, so a blocked ad frame collapses (0×0 in Edge) instead of showing the placeholder.
- **Quiet**: a blocked ad request never loads `blocked.html`, so nothing is reported. The popup says "חסימת פרסומות פעילה" while it is on.
- **Package**: the ruleset is 1.17 MB (449 KB gzipped); the zip grows from about 60 KB to 520 KB. The browser also keeps its own index of every static ruleset, disabled ones included: Edge writes it to `_metadata/` inside an unpacked extension's folder, so a store zip must come from a fresh `npm run build`, never from a `dist/` that a browser has loaded.

### The parents' baseline protection (PROTECTION-SPEC §13)

Administrators and unrestricted members (the parents, other adults) get the family's baseline protection: mode `baseline` in the hello and the rules reply while any of its four switches is on, `unrestricted` (as before) when all are off. Children, teens and unlinked standard accounts are unchanged.

- **What applies**: the rules reply's compiled rules (the family's `adult` list as one or a few block rules in the global band, the parents' own allow rules above it in the member band; no default block, no IP-literal gate, no YouTube rule, no time-up rules), `features {jumpGuard, blockAds}` from the switches with `canOverrideJump: true` and `blockYouTubeShorts`, `logSearches` false, YouTube `unrestricted`, time `unlimited` (no badge, no warnings). SafeSearch is a browser policy the service writes; the extension does nothing for it.
- **Block page**: `blocked_baseline_adult` ("אתר למבוגרים — חסום בהגנה הבסיסית של המשפחה.") with no request button and the line "אפשר לכבות את ההגנה הזו בממשק הניהול של WebFilter, בדף ההגדרות" (`#baseline-hint`). A reason guessed from the installed rules (`explain.ts`) is `blocked_baseline_adult` too. A jump block offers "פתח בכל זאת".
- **Nothing is reported**: in this mode the worker never sends `reportBlock` (the block page asks with `decideUrl`, which records nothing; a jump block asks nothing), `reportOverride`, `reportSearch` or `requestAccess`, whatever the features say; the service also drops them for these accounts. Heartbeats are sent as for unrestricted users; the service counts no time for them.
- **YouTube** is never filtered for a parent (`decideYouTube` treats `baseline` like `unrestricted`).
- **Service down**: the native host's own answer for an administrator or an unrestricted member is `unrestricted` as before, with no rules or features: the baseline (adult list, jump guard, ads) is off until the service is back, and nothing is blocked more than before. Disconnected (no host at all) is fail-closed for everyone, as before.
- The popup shows the mode "הגנה בסיסית להורים" and "שום דבר מהגלישה שלך לא נרשם".
- **An older extension** with a newer service gets mode `baseline` in the hello and treats it as a filtered mode: it installs the rules and the features, and the service answers its reports with the right reason and no request (and records nothing).

**Session rule ids**: ids from 1,000,000,000 up belong to the extension (Shorts 1,000,000,001; jump-guard tabs from 1,100,000,000). The compiler's ids stay below (hashed ids < 1,000,000,000), and the time-up rule replacement never touches the extension's. Fail-closed, inert and unrestricted clear them. Static rule ids (`failclosed`, `ads`) are per ruleset and never meet these.

### Window titles (lab automation)

`blocked.html` → `WebFilter · חסום`, `timeup.html` → `WebFilter · הזמן נגמר`, `my-channels.html` → `WebFilter · הערוצים שלי`, in every UI language. The pages also expose `data-reason`, `data-url`, `data-reason-source`, `data-request-result` and `data-ready` on `<html>` for level-3 runners.

## Decisions to review

- **Test hooks are a separate build** (`dist-test/`), in the spirit of CLAUDE.md rule 7. The production build checks that `background.js` contains none. The hook can only make the extension stricter (simulate `admin`).
- **Unreadable install type → enforce.** If `getSelf()` fails three times the extension behaves as policy-installed. This would block a reviewer's browser in that (unlikely) case.
- **A channel in both `youTube.allowed` and `youTube.blocked` counts as blocked.** The service flattens member and global records into two lists, so it should send the effective record per channel.
- **Warnings re-arm after more time is granted**, rather than strictly once per day.
- **No request button** for homework, YouTube off, an unknown channel, or the fail-closed and service-down pages, even if the service says `canRequest`.
- **Heartbeats are sent for unrestricted users too** (and for parents in the baseline). The service ignores them, and this keeps the code path single.
- **A parent's baseline is off while the service is down** (the host answers unrestricted as before), rather than kept from the last rules: the native host cannot compile it, and a stopped service must never block a parent more than it used to.
- **`webNavigation`** is used to recover the fail-closed page's URL, to block in-page navigations, and to catch YouTube SPA navigations. **`tabs`** is needed to read tab URLs for heartbeats and time-up moves. The protection features need no new permission (`webNavigation.onCreatedNavigationTarget` / `onCommitted`, session rules with `tabIds`), nor does the parents' baseline (dynamic rules, the existing `ads` ruleset and the jump guard).
- **Jumps and the URL rules**: a jump is blocked whether or not the target is allowed by the rules (the tab rule outranks them), so a child sees "the site tried to open another site" even for an allowed target, and "open anyway" never bypasses the rules (the opened URL is filtered as usual).
- **Middle-click and "open link in new tab"** to another site count as jumps: the browser reports them like `window.open`. **Sign-in is not a jump** (decided with the user): a popup or client redirect to an exact sign-in host (`SIGN_IN_HOSTS` in `src/shared/jump.ts`: Google accounts, Microsoft sign-in, Apple ID) and the provider's return to the site are allowed; the URL rules still decide whether the host is allowed.
- **Not caught as jumps**: a script that navigates the page to another site after it finished loading (a timer, a click handler) and an auto-submitted form — Edge reports both like a link click (`link` / `form_submit`, no `client_redirect`). Also, once an opened tab shows a page of the opener's site, a later `opened.location = …` from the opener looks like a click in that tab. After a client-redirect block, Back returns to the page that had committed (the member's own action).
- **Click-through exemption** for Bing, DuckDuckGo, Google and YouTube redirect pages, so search results work; other link shorteners that redirect by script or meta refresh (t.co, l.facebook.com, …) are blocked as jumps.
- **Image search block page offers no request** (`requestActionFor` → none), like homework: an approval of the URL would not lift the member setting.
- **Search log**: blocked searches (from the block page's first report) are logged too; reloads and Back/Forward never are; the de-duplication window is 10 minutes from the report.
- **Ad blocking while fail-closed is on**, while the native host answers by itself it is off (no features: only always-allowed sites load), and an unlinked account never has it (like every feature). EasyList's exceptions are honoured per host, more widely than written (a host spared for one file on some sites is not blocked at all there), and a host spared on every site is not blocked anywhere (`amazon-adsystem.com`, `pubads.g.doubleclick.net`). No per-site exceptions yet: the parent's switch is the way out.
